# Robi v0.3.29 — 電供 USB 連線等待與錯誤診斷

基準 v0.3.28；保留舊版。

使用者實機診斷：COM7／115200，開埠等待 1 秒，以 LF 與 CRLF 發送 *IDN? 並在 3 秒窗口接收，兩次皆收到 38 bytes、LF 結尾的 GPP-6030 V1.07 識別。這證明該次 USB 路徑及指令可用，尚不能分辨初始化等待與回覆逾時各自的影響。

修改：SERIAL 開埠後等待 1 秒、清除開埠期間接收緩衝，再發出識別查詢；讀取逾時由 0.8 秒改為 3 秒，寫入逾時由 0.5 秒改為 1 秒。維持 LF 結尾及唯讀白名單，不接受不完整數字，不自動重送避免回覆錯配。錯誤補上指令、無資料／不完整回覆、長度、原始 bytes 與 hex。

操作：解壓到獨立資料夾，關閉 PowerShell 診斷與舊版 Robi，再開 start_windows.bat。實機解鎖，電供啟用、SERIAL、COM7、115200、間隔 1 秒，CH2 先不勾，套用後等待數秒。先核對電供讀值，不需開始馬達測試。若失敗，提供完整操作紀錄，新版可指出具體失敗查詢。

未修改電供電壓、限流、輸出狀態、量測換算、PID、實驗流程或介面布局。TA612C 尚未接入；48 V 韌體、Windows GUI／DPI 與本修正版電供實機仍待驗證。沒有操作硬體。

驗證結果以 validation/v029/full.txt 為準；新增 SERIAL 路徑測試涵蓋現場識別回覆、初始化參數、空回覆／部分回覆的區分、初始化失敗關閉連線、拒絕不完整量測。離線測試不等同實機修復已確認。

實際結果：完整執行 128 項中，119 通過、6 GUI 跳過、3 項新增測試因環境未安裝 serial 而發生測試設置錯誤。將新增測試改為注入模擬 serial 模組後，重跑這 3 項全數通過；正式程式未因此更動。合計 122 項通過、6 項跳過，並非修正後再次完整跑完的單輪統計。
